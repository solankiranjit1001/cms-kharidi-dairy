# હિસાબનાં સૂત્રો (Accounting formulas)

જથ્થો (kg/નંગ…) અને રકમ (₹) હંમેશાં અલગ રાખવામાં આવે છે. બધી રકમ સર્વર ગણે છે (પૈસા સુધી ચોક્કસ, દશાંશ ભૂલ વગર).

| વિગત | સૂત્ર |
|---|---|
| પંક્તિની રકમ | જથ્થો × દર (પૈસામાં round half-up) |
| ચોખ્ખી ખરીદી | ખરીદી − વેપારીને પરત |
| શરૂઆતનો સ્ટોક ₹ | આગલા દિવસે (અથવા છેલ્લા સાચવેલા દિવસે) દાખલ કરેલ ક્લોઝિંગ મૂલ્ય |
| ક્લોઝિંગ સ્ટોક ₹ | દરરોજ જાતે દાખલ કરેલ મૂલ્ય (માલિકનો નિર્ણય). એપ માત્ર સૂચન આપે છે: જથ્થો × સરેરાશ ખરીદી દર |
| વેચાયેલ માલની પડતર (COGS) | શરૂઆતનો સ્ટોક ₹ + ચોખ્ખી ખરીદી − ક્લોઝિંગ સ્ટોક ₹ |
| કુલ નફો | ચોખ્ખું વેચાણ (છૂટ બાદ) − પડતર |
| દૈનિક પરિણામ | કુલ નફો − ખર્ચ |
| રોકડ હિલચાલ (નફો નથી) | વેચાણની આવક − વેપારીને ચુકવણી − ખર્ચ |
| વેપારી બાકી | શરૂઆતની બાકી + ખરીદી − પરત − ચુકવણી ± માલિકે મંજૂર કરેલ સુધારો |
| ગણતરી સ્ટોક (જથ્થો) | શરૂઆત + ખરીદી − વેચાણ − બગાડ − પરત ± સુધારો |

## નિયમો
* **ક્લોઝિંગ સ્ટોક ખર્ચ નથી.** તે પડતરમાંથી બાદ થાય છે.
* **બગડેલ માલ ફરી બાદ થતો નથી.** તેની કિંમત ખરીદીમાં છે અને તે ક્લોઝિંગ સ્ટોકમાં નથી, એટલે પડતરમાં આપમેળે આવી જાય છે. તેનું અંદાજિત ₹ મૂલ્ય માત્ર માહિતી માટે બતાવાય છે.
* **વેપારીને ચુકવણી નફામાંથી બાદ થતી નથી** — ખરીદી પહેલેથી પડતરમાં ગણાઈ છે. ચુકવણી માત્ર વેપારી બાકી અને રોકડ હિલચાલ બદલે છે.
* **ટ્રાન્સપોર્ટ/હમાલી** અલગ ખર્ચ તરીકે નોંધાય છે (માલની પડતરમાં ઉમેરાતાં નથી).
* ક્લોઝિંગ મૂલ્ય દાખલ ન થાય ત્યાં સુધી તે દિવસનો નફો "બાકી" બતાવાય છે — અંદાજથી ભરવામાં આવતો નથી.
* વેચાણ, બગાડ, પરત અથવા ઘટાડાનો સુધારો કોઈ પણ તારીખે સ્ટોક માઇનસ કરી શકતા નથી (પાછલી તારીખની એન્ટ્રી પછીના દિવસોને અસર કરે તો પણ).

## ઉદાહરણ
શરૂઆત ₹3,000; ખરીદી ₹1,000; ક્લોઝિંગ ₹3,350; વેચાણ ₹900; ખર્ચ ₹100; ચુકવણી ₹1,000; બગાડ 5 kg.
પડતર = 3,000 + 1,000 − 3,350 = ₹650 → કુલ નફો = 900 − 650 = ₹250 → પરિણામ = ₹150.
રોકડ હિલચાલ = 900 − 1,000 − 100 = −₹200 (નુકસાન નથી; વેપારીની બાકી ઘટી).
આ ઉદાહરણ `test/business.test.js` માં આપમેળે ચકાસાય છે.
